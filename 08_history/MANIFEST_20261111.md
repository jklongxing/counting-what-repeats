# Data bundle for "Supervision and Readout for Action-Conditioned Counting in Natural Videos"

Created 2026-11-11. This folder contains every artifact needed to audit the numbers in
`JVCI_Counting_What_Repeats.docx`. Nothing here was edited by hand: the JSON and JSONL files
are copied verbatim from the run directory on the experiment server, and every table in the
paper is regenerated by one of the scripts in `07_scripts/`.

## What is in each folder

| Folder | Contents | Count |
|---|---|---|
| `01_benchmark/` | The benchmark itself: unit list, split assignment, construction statistics, external VAL units, human-written question units | 5 |
| `02_predictions/` | **Per-question predictions**, one JSONL per configuration. Each line is one question with `unit_id`, `video_id`, `action`, `split`, `count` (gold), `pred` (model answer), and the raw answer string | 110 |
| `03_scores/` | Per-question **answer scores** over the digits 1-8 for the LoRA adapter (four shards), used by the output-calibration baselines | 4 |
| `04_summaries/` | Aggregate results: scoring summaries, paired tests, ablations, label audit, calibration, same-video analyses | 99 |
| `05_figures/` | The eight manuscript figures at 300 dpi plus the graphical abstract | 9 |
| `06_documents/` | The manuscript (DOCX and Markdown source), cover letter, earlier result records and the two independent review memos | 17 |
| `07_scripts/` | The scripts that produce every table and figure | 20 |

Total: 264 files, about 19 MB.

## How to check a number

Every number in the paper comes from `04_summaries/canonical_results.json`, produced by
`07_scripts/canonical_eval_v2.py` from `01_benchmark/benchmark3_units.jsonl` and the
predictions in `02_predictions/`. To recompute a single cell:

1. Pick the run from the table below.
2. Open its file in `02_predictions/` and count `pred == count` (or the four-way bucket, where
   counts above 4 are pooled to 4).
3. The definition of each metric is in Section 4.0 of the manuscript and in the docstring of
   `canonical_eval_v2.py`.

## Provenance facts worth stating in a data-availability section

- Benchmark construction is deterministic: a fixed source zip (SHA-256 recorded in
  `01_benchmark/benchmark3_stats.json`), a fixed seed (20261105), and fixed grid rule
  (`fixed_grid` in the construction script).
- Splits are assigned at the video level with zero video overlap; the assignment is frozen in
  `01_benchmark/benchmark3_splits.json`.
- The scoring rule is fixed before evaluation: every question in the 3,710-unit universe is
  scored, an unparsable answer counts as an error, and counts of 5 and above are pooled into
  a 4+ bucket.
- Paired intervals resample videos, not questions, because several questions come from the
  same video.

## Deprecated artefacts

`04_summaries/same_question_bootstrap.json` and `07_scripts/same_question_bootstrap.py` record a two-way cluster bootstrap for the same-question comparison that was **withdrawn** from the manuscript. The pairs share videos across pairs, and the implementation weighted pairs by `sa + sb - sa*sb`, which can produce negative weights; a defensible interval would need either a pre-specified globally disjoint subset or a corrected multi-way scheme. The manuscript now reports that comparison descriptively, without a p value or interval. Keep these files as a record of the withdrawn analysis, not as the paper's method.
## Regeneration note for the Countix table

`02_predictions/countix_refit_seed0.jsonl` through `seed4.jsonl` all come from one run: five seeds fitted on the same 1,290 training clips, evaluated on the same 476 clips. Recomputing the mean from these five files must reproduce 56.47% (sd 0.95). An earlier revision mixed files from a run that still contained a source video present in evaluation; that mixture is not the reported result.
